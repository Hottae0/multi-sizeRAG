# multi-sizeRAG

**청크 크기가 달라지면 새로운 사실, 기존 사실의 구체화, 같은 사건의 다른 측면을 포착할까요?**

최종 목표는 이 상호보완성을 활용하는 새로운 GraphRAG 방법론입니다.
현재 Experiment 1에서는 크기별 그래프의 유효한 차이를 먼저 검증합니다.
Fusion·progressive refinement·검색·QA 개선은 아직 검증하지 않았습니다.

## 지금 하는 실험은 몇 개인가요?

**하나의 Experiment 1 안에 문서당 추출 조건 5개와 핵심 분석 2가지가 있습니다.**
문서 수를 1→5→20으로 늘리는 것은 같은 실험의 규모 확장입니다.

### 1. 문서당 그래프 5개를 만듭니다

|조건|청크 크기|Seed|역할|
|---|---:|---:|---|
|A|128|17|크기별 비교를 수행합니다.|
|B|256|17|크기별 비교 및 주 비교의 공통 기준입니다.|
|C|512|17|크기별 비교를 수행합니다.|
|D|1024|17|크기별 비교를 수행합니다.|
|E|256|29|같은 크기의 독립 반복을 대조합니다.|

모두 **같은 문서의 처음부터 끝까지** 처리합니다. Boundary=0, overlap=0이며 마지막 짧은 청크도 포함합니다.
청크마다 entity·relation을 추출하고, 같은 조건의 추출물을 모아 문서 전체 그래프를 만듭니다.
추출 청크와 원문 근거는 그래프를 만든 뒤에도 추적할 수 있습니다.
그래프 5개는 LLM 호출 5회를 뜻하지 않습니다. 조건별 청크 수만큼 호출합니다.

주 분석은 **추출 → 의미 정렬 → 조건별 그래프 → 비교 → 독립 원문 판정**으로 진행합니다.
추출 직후 저장하는 literal 그래프는 오류 점검용이며, 의미 정렬 후 semantic 그래프와 구분합니다.
의미 정렬과 원문 판정에는 별도 검토가 필요하며 자동으로 정답을 생성하지 않습니다.

### 2. 핵심 분석은 두 가지입니다

|분석|비교 구성|확인할 질문|
|---|---|---|
|크기별 상호보완성|128–256, 128–512, 128–1024, 256–512, 256–1024, 512–1024: **6쌍**|어떤 유효 관계·근거·연결을 서로 보완하는지 확인합니다.|
|반복 대비 다른 크기 추가|**256(seed17)+256(seed29) 대 256(seed17)+512(seed17)**|같은 크기를 다시 추출하는 것보다 다른 크기를 추가하는 것이 도움이 되는지 확인합니다.|

Jaccard는 대칭이지만 신규 관계는 방향별로 다릅니다. 크기별 6쌍은 12방향이며,
동일 크기 반복의 양방향 2개를 더해 모드당 문서당 14방향을 계산합니다.
기존 v1 주 비교는 공통 G256(seed17)에 추가되는 **원문 지지 AND 의미적으로 새로운 관계**의 수와 비용을 비교했습니다. 새 측정은 정보 추가 유형과 다른 측면을 분리하고 비용은 참고로 둡니다.
표현만 다른 관계나 원문이 지지하지 않는 관계를 유효 신규 관계로 세지 않습니다.

### 3. 전체 원문 1→5→20문서로 확장합니다

|단계|누적 문서|조건별 그래프|목적|
|---|---:|---:|---|
|첫 개발 실행|1|5개|전체 파이프라인·오류·시간·메모리·사례를 확인합니다.|
|개발군 확대|5|25개|현상을 확인하고 최종 설정을 고정합니다.|
|본 평가|20|100개|새로운 15문서를 평가하고 개발/평가 결과를 분리합니다.|

선택한 문서는 어느 단계에서도 일부 구간만 처리하지 않습니다.
개발군은 Novel-10146, Novel-30752, Novel-41603, Novel-44557, Novel-54537입니다.
기본 첫 문서는 Novel-10146입니다. 같은 설정이면 먼저 처리한 결과를 재사용하며,
설정을 바꾸었다면 새 study에서 개발 문서도 다시 처리합니다.

한 문서의 추출·오류 점검·그래프 저장을 완료한 뒤 다음 문서로 진행합니다.
의미 정렬·독립 원문 판정은 문서별로 별도 진행합니다.
평가 15문서는 프로토콜 동결 후에만 추출합니다. 평가 결과가 유리하도록 설정을 변경하지 않습니다.
Boundary64나 다른 크기의 seed29 반복은 현재 기본 5조건에 포함하지 않은 후속 대조군입니다.

## 유효 신규 관계는 어떻게 측정하나요?

**유효 신규 관계는 “원문이 지지하면서, 기준 그래프에는 같은 의미의 사실이 없는 관계”입니다.** 단순히 edge 문자열이 다르거나 그래프가 커졌다는 이유로 세지 않습니다.

**① 의미 정렬 후 신규 후보와 공통 관계를 나눕니다.**

기준 그래프는 G256(seed17)입니다. 여기에 G256(seed29)를 추가하는 경우와 G512(seed17)를 추가하는 경우를 각각 평가합니다. 모든 조건의 boundary는 동일하게 맞춥니다.

먼저 원문을 바탕으로 개체의 별칭과 관계의 동치 표현을 정렬합니다. 예를 들어 같은 인물을 가리키는 Tom/Thomas와 같은 고용 사실을 뜻하는 works for/is employed by는 중복일 수 있습니다. 이름이나 표현이 비슷하다는 이유만으로 합치지 않으며, 방향·극성·시점·조건·발화자를 확인합니다. 의미 정렬에는 검토된 정렬 파일이 필요합니다.

정렬된 추가 그래프에서 기준 그래프에 없는 edge를 신규 후보로, 양쪽에 있는 edge를 공통 관계로 나눕니다. 이 단계의 신규 후보에는 환각이나 정렬 오류가 남아 있을 수 있습니다. 집계 단위는 중복 제거된 관계 edge이며, 여러 청크에서 같은 관계가 반복된 occurrence를 각각 새로운 사실로 세지 않습니다.

**② 원문 지지와 의미적 신규성을 독립적으로 판정합니다.**

- **원문 지지(supported):** 전체 원문이 해당 주체·관계·대상과 방향·부정·시점·조건을 실제로 지지하는지 확인합니다. 인용 문장이 원문에 있다는 사실만으로 통과시키지 않습니다.
- **의미적 신규성(semantically_novel):** 기준 그래프의 전체 claim에 같은 의미의 사실이 이미 표현되어 있는지 확인합니다. 단순 표현 차이는 신규 관계로 인정하지 않습니다.
- 두 항목이 모두 true일 때만 유효 신규 관계로 판정합니다. 미판정·불확실 항목을 false로 채우지 않습니다.

예를 들어 기준 그래프에 “Alice는 X회사에서 근무합니다”가 있을 때 다음과 같이 구분합니다.

- “Alice는 X회사에 고용되어 있습니다”가 같은 사실을 뜻한다면 의미 중복입니다.
- “Alice는 Y프로젝트를 관리합니다”가 원문으로 지지되고 기준 그래프에 없다면 유효 신규 관계입니다.
- “Alice는 X회사를 설립했습니다”가 원문으로 지지되지 않는다면 새로운 표현이어도 추출 오류입니다.

**③ 조건을 가린 층화 표본을 두 판정자가 검토합니다.**

문서 × 비교 방향 × 신규/공통 층별로 무작위 표집합니다. 현재 코드의 기본값은 층마다 최대 20개이며, 모집단이 20개보다 작으면 전수 검토합니다. 최종 표집 수와 판정 정책은 개발군에서 검토한 뒤 평가군 실행 전에 고정합니다.

판정자에게는 크기·seed·boundary·신규/공통 층을 숨기고, 판정할 claim·전체 원문·기준 그래프의 전체 claim을 제공합니다. 두 판정자가 독립적으로 검토한 뒤 불일치를 조정하여 최종 판정 파일을 작성합니다. 현재 코드는 최종 판정 파일을 집계하며, 두 사람의 독립 검토나 불일치 조정을 자동 수행하지 않습니다.

공통 관계도 표집하는 이유는 실제로 다른 사실을 잘못 합친 정렬 오류를 점검하기 위해서입니다. 이 감사만으로 전체 의미 정렬이 자동 수정되거나 완전해지는 것은 아닙니다.

**④ 직접 확인한 수와 전체 추정치를 구분합니다.**

각 표본의 포함확률은 해당 층의 표집 수를 모집단 수로 나눈 값입니다. 표본에서 확인한 유효 신규 관계마다 포함확률의 역수를 가중치로 적용하는 Horvitz–Thompson(HT) 추정치를 계산합니다.

유효 신규 수 추정치 = Σ [원문 지지 AND 의미적 신규성의 판정값 ÷ 포함확률]

예를 들어 신규 후보 100개 중 20개를 무작위 검토하여 12개가 유효 신규로 확인되었다면, 해당 층의 추정치는 100 × 12/20 = 60개입니다. **직접 확인한 수는 12개이고, 60개는 추정치입니다.**

현재 코드의 `observed_valid_novel`은 표본에서 직접 확인한 수이며, `estimated_valid_novel`은 신규·공통 두 층의 가중 추정치를 합한 값입니다. 신규 후보층에서 유효한 비율은 별도 지표로 보고합니다. 필요한 표본 판정이 완료되지 않으면 최종 추정치는 `null`로 남깁니다.

**⑤ 같은 크기 반복과 다른 크기 추가의 효과·비용을 비교합니다.**

문서별 주 비교는 다음과 같습니다.

Δ = 유효 신규 수 추정치[G512(seed17) | G256(seed17)] − 유효 신규 수 추정치[G256(seed29) | G256(seed17)]

Δ가 양수이면 해당 문서에서는 다른 크기를 추가했을 때 더 많은 유효 신규 관계가 추정된다는 뜻입니다. 음수이면 같은 크기 반복 쪽이 더 많다는 뜻입니다. 양수라는 사실만으로 통계적 유의성이나 동일 비용에서의 우수성을 주장하지 않습니다.

개발 5문서와 평가 15문서의 문서별 결과·문서 macro 평균·대응 차이를 구분하여 보고합니다. 추가 호출 수·입출력 토큰·시간·비용을 함께 비교하며, 유효 신규 관계당 추가 시간·금액도 확인합니다. 추정치가 0이거나 필요한 비용 기록이 없으면 해당 비율은 `null`로 둡니다. 실패·제외 문서에 사용한 비용도 숨기지 않습니다.

**현재는 측정 절차와 집계 기능을 구현한 상태입니다. 실제 전체 원문 의미 정렬과 독립 판정은 아직 수행하지 않았습니다.** 이 지표는 기준 그래프에 대한 추가 정보의 추정치이며, 원문 전체의 gold recall·경로 recall이나 GraphRAG의 QA 개선을 의미하지 않습니다.

이 저장소는 여러 크기의 청크에서 추출한 지식을 통합하는 GraphRAG 아이디어의 전제를 확인하기 위한 탐색 실험이다. 현재는 동일 원문의 청킹, Qwen 기반 entity·relation 추출, 결과 비교와 오류 분석까지 진행했다. 여러 그래프를 통합한 검색 시스템이나 QA 성능 개선을 구현·검증한 단계는 아니다.

## 1. 어떤 문제의식에서 시작했는가

출발점은 기존 논문 미팅에서 다뤘던 **추출용 청크 크기와 검색용 청크 크기를 나누어 비교하는 실험**이다. 지식을 추출할 때 필요한 문맥의 범위와, 검색 후 답변에 제공할 때 필요한 문맥의 범위가 같아야 하는지에서 질문이 이어졌다.

여기서 초기 연구 구상은 “최적의 청크 크기 하나를 선택하는 대신, 여러 크기에서 얻은 entity–relation–entity를 정렬하고 근거와 함께 통합할 수 있을까?”로 확장됐다. 작은 청크는 국소적인 사실에 집중할 수 있고, 큰 청크는 여러 문장에 걸친 문맥을 보존할 수 있다는 기대가 있다. **이는 실험을 시작하게 된 가설이며, 현재 입증된 성질은 아니다.** 큰 청크에서도 세부 사실이 누락되거나 잘못 연결될 수 있다.

따라서 통합 시스템을 먼저 만드는 것보다, 같은 원문에서 크기별로 얻는 관계가 실제로 다른지, 그 차이가 원문으로 지지되는지부터 확인하기로 했다. 이 저장소는 그 첫 단계의 기록이다. 기존 미팅 자료에서 얻은 문제의식과 아래 선행연구의 기여는 구분한다.

### KET-RAG와의 연결점과 차이

[KET-RAG: A Cost-Efficient Multi-Granular Indexing Framework for Graph-RAG](https://arxiv.org/abs/2502.09304)는 서로 다른 세밀도의 표현을 결합하면서 그래프 구축 비용을 줄인다는 점에서 관련된 선행연구다. 핵심 청크를 선택해 만든 knowledge graph skeleton과 전체 청크의 text–keyword 이분 그래프를 함께 활용한다. 이 연구를 검토하며 **여러 표현을 결합하는 이득이 추가 비용을 정당화하는가**를 본 실험에서도 확인해야 할 문제로 삼았다.

|관점|KET-RAG|이 저장소의 연구 구상|
|---|---|---|
|주요 설계|선택적으로 추출한 KG skeleton과 text–keyword 그래프 결합|동일 원문을 여러 청크 크기로 나누어 추출한 관계의 정렬·통합|
|먼저 확인할 문제|인덱싱 비용과 검색·생성 품질의 균형|크기별로 추가되는 관계가 유효하고 상호보완적인가|
|현재 검증 범위|논문에서 제시한 인덱싱·검색·생성 평가|로컬 추출 파일럿과 진단 사례 분석|

KET-RAG에도 sub-chunk 분할을 활용하는 설계가 있으므로, “여러 크기를 사용한다”는 사실만으로 차별성을 주장할 수 없다. 이 구상이 기여가 되려면 **동일 비용의 단일 크기 반복 추출보다 유효한 관계를 더 확보하고, 그 이득이 검색·QA까지 이어지는지**를 보여야 한다. 현재 KET-RAG를 재현하거나 직접 비교한 결과는 없다. 관련 구현 설명은 [KET-RAG 논문 §5](https://arxiv.org/html/2502.09304v1#S5)를 참고한다.

## 2. 어떤 데이터셋을 사용했고, 왜 선택했는가

사용 데이터는 **GraphRAG-Bench의 Novel corpus**이며, 공식 [GraphRAG-Benchmark 저장소](https://github.com/GraphRAG-Bench/GraphRAG-Benchmark)의 `Datasets/Corpus/novel.json`을 내려받았다. 이 벤치마크는 그래프 기반 RAG를 사실 검색부터 복잡한 추론, 문맥 요약 등으로 평가한다. 데이터셋 배경은 [When to use Graphs in RAG](https://arxiv.org/abs/2506.05690)에 설명되어 있다.

이번 단계에서 이 corpus를 선택한 이유는 다음과 같다. 이는 본 실험의 선택 근거이며, 데이터셋 논문이 청크별 상호보완성을 보장한다는 뜻은 아니다.

- **연속된 긴 원문을 직접 나눌 수 있다.** 같은 구간을 고정한 채 크기만 바꿀 수 있어, 서로 다른 내용을 비교하는 혼선을 줄일 수 있다.
- **문맥에 따른 관계 추출을 살펴볼 수 있다.** 서술 속 인물·장소·대명사·별칭과 여러 문장에 걸친 정보를 통해, 경계가 관계를 끊는지 또는 넓은 문맥이 도움이 되는지를 관찰하려 했다.
- **후속 검색·QA 평가와 연결할 수 있다.** 추출 단계에서 의미 있는 효과가 확인되면 같은 벤치마크의 후속 과제로 확장할 수 있다. 이번에는 질문·정답을 사용하거나 공식 QA 점수를 계산하지 않았다.
- **로컬 파일럿의 입력을 재현할 수 있다.** 공개 원문에서 작은 구간을 고정하고, 원문 해시와 문자·토큰 위치를 보존해 실제 모델 출력을 추적할 수 있다.

### 실제로 사용한 범위

|항목|이번 실험에서 사용한 내용|
|---|---|
|다운로드한 corpus|`novel.json`의 문서 20개|
|선택 방법|고정 seed `20261015`로 문서 2개 선택, 각 문서의 중간 범위에서 문장 뒤를 시작점으로 선정|
|실제 추출 입력|문서별 연속 1,024 모델 토큰, 총 2,048토큰|
|`Novel-10146`|호텔·거리·건축자·화재 등을 다루는 도시 기록 구간|
|`Novel-44557`|장소·방문·인물 간 대화를 포함한 여행 서술 구간|
|사용하지 않은 것|문서 전체에 대한 추출, 벤치마크 질문·정답 및 공식 QA 평가|

두 문서는 내용 유형을 보고 의도적으로 고른 것이 아니라 고정 seed 표본이며, 표의 내용 설명은 추출 후 확인한 것이다. corpus 이름은 Novel이지만 이번 두 구간을 전형적인 소설 전체나 모든 장문 문서의 대표 표본으로 보지 않는다. 선택 구간과 위치·해시는 [실험 manifest](experiments/pilot/pilot_raw/manifest.json)에 보존했다.

또한 이번에 사용한 원문에는 이 실험용으로 독립 주석한 entity·relation 정답 그래프가 없다. 따라서 추출량과 원문 대조 사례는 볼 수 있지만, 이 결과만으로 gold 기준 precision·recall을 주장할 수는 없다. 관계 정답 주석을 이용하는 후속 평가도 필요하다.

## 3. 무엇을 확인하려는 실험인가

핵심 가설은 **“청크 크기별로 서로 다른 유효 관계를 얻으며, 이를 합치면 단일 크기보다 원문 정보를 더 잘 보존할 수 있다”**이다. 이 가설을 확인하려면 아래 세 질문을 순서대로 통과해야 한다.

1. **차이가 있는가?** 같은 원문·모델·프롬프트에서도 크기에 따라 entity와 relation의 집합이 달라지는가?
2. **그 차이가 유효한가?** 별칭·동의 표현·관계 방향 차이를 정렬한 뒤에도 원문이 지지하는 고유 사실이 남는가?
3. **추가 비용만으로 설명되지 않는가?** 같은 크기를 여러 번 추출하거나 더 많은 출력 예산을 주는 것보다 여러 크기를 결합하는 것이 나은가?

이번에는 첫 질문을 실제 출력으로 확인하고, 두 번째 질문을 일부 사례와 부분 정렬로 탐색했다. 세 번째 질문의 비용 통제 실험과 최종 검색·QA 평가는 아직 수행하지 않았다.

### 실험 조건

동일한 1,024토큰 구간을 E128/E256/E512/E1024로 나누고 overlap 없이 추출했다. 각 크기의 청크 결과를 원래 문서 구간 단위로 합쳐 중복을 제거한다. E1024는 **문서 전체가 아니라 선택한 구간 전체를 한 번에 입력한 조건**이다.

추출기는 로컬에 설치된 **Qwen3-VL-4B-Instruct Q4_K_M**이며 텍스트만 입력했다. 로컬에서 실행 가능한 모델로 가설을 빠르게 점검하려는 선택이고, 최고 품질의 추출기라는 가정은 하지 않는다. 현재 결과는 이 모델·양자화·프롬프트 설정에 한정된다.

- 기본 seed 17로 크기를 비교하고, E256은 seed 29를 추가해 동일 크기에서도 출력이 변하는지 확인했다.
- 처음 36회는 E128/E256/E512와 E256 반복 조건이다. 이후 동일 설정의 E1024 2회를 추가했다.
- 호텔 기록의 E1024가 출력 상한에 걸려, 상한을 늘린 별도 진단 1회를 추가했다. 이를 동일 설정 비교에 합치지 않는다.
- 이름 기반 관계 연결 방식도 별도로 4회 시험했지만, 출력 검증 실패로 개선 효과를 확인하지 못했다.

전체 설계와 아직 실행하지 않은 확대 계획은 [실험 설계](experiments/pilot/실험설계.md)에 구분해 기록했다.

## 4. 현재 관찰과 해석

아래 값은 기본 seed 17에서 중복을 제거한 **entity 명칭 / ID로 연결 가능한 relation의 문자열 수**다. 유효한 사실의 수나 정확도 점수가 아니다.

|청크 크기|호텔 기록 `Novel-10146`|여행 서술 `Novel-44557`|
|---|---:|---:|
|128|62 / 38|15 / 17|
|256|58 / 42|17 / 11|
|512|61 / 50|20 / 18|
|1024|동일 출력 상한에서 잘림|9 / 7|

호텔 기록은 E1024의 최대 출력을 4,096에서 6,144토큰으로 늘린 별도 진단에서 **49 / 30**으로 완료됐다. 출력 상한이 다르므로 위의 정상 완료 조건과 같은 조건의 결과로 취급하지 않는다.

**관찰된 차이에는 상호보완 후보와 오류가 함께 섞여 있다.** E128에서는 소녀의 Board School 미방문 관계가, E512에서는 Devil’s Frying Pan과 Cadgwith의 위치 관계가 원문 지지 사례로 확인됐다. 반면 E1024에서는 Cadgwith를 언급한 근거로 Lizard에 연결하는 오류가 나타났다. 근거 문장이 원문에 존재하는지만 검사해서는 이런 오류를 잡을 수 없다.

또한 여행 문서 E256/E512의 관계 Jaccard는 문자열 비교에서 0.000이었지만, 별칭·관계 방향을 부분 정렬한 뒤에는 **0.160**이었다. 처음 보인 차이의 일부는 새로운 사실이 아니라 표현 차이였다. E256에서 seed만 바꿔도 결과가 달라져, 청크 크기 효과와 추출기의 변동을 분리해야 한다.

따라서 현재 말할 수 있는 것은 **“크기에 따라 추출 결과가 달라지고 일부 상호보완 후보가 있지만, 유효한 추가 지식과 추출 오류를 더 구분해야 한다”**까지다. 큰 청크의 우월성, 여러 크기 통합의 효과, KET-RAG 대비 우위는 아직 입증하지 않았다. 사례 판정은 assistant의 원문 대조이며 독립적인 사람 주석이나 무작위 precision 표본이 아니다.

## 5. 다음에 무엇을 검증할 것인가

우선 별도 문서·구간으로 표본을 늘리고, 각 크기의 여러 seed 및 문장 경계 조건을 비교한다. 정렬 규칙은 개발 표본에서 고정한 뒤 평가 표본에 적용하고, 크기·seed를 가린 사람 검토로 원문이 지지하는 고유 관계를 확인해야 한다.

그다음 **다중 크기의 합집합과 동일 비용의 단일 크기 반복 추출**을 비교한다. 추가 호출 덕분에 관계가 늘어나는 것인지, 다른 문맥 범위 자체가 도움이 되는지를 분리하기 위해서다. 이 단계에서 유효한 추가 관계가 확인되면 근거를 보존한 그래프 통합, 검색, QA와 비용 평가로 확장한다. 관계 정답 주석이 있는 Re-DocRED 활용은 후속 후보이며 아직 실행하지 않았다.

## 출력 잘림 재추출 — 2026-10-16

기존 **Qwen3-VL-4B-Instruct Q4_K_M**에서 잘렸던 15건만 context 65,536, 생성 상한 `max_tokens=-1`로 다시 실행했다. **7B 모델 실험은 아니다.** 약 5시간 49분 동안 실행해 13건은 종료·파싱에 성공했고, 2건은 context 한계에서 다시 잘렸다. 원본 1,140건은 보존했다.

복구 결과를 포함하면 완전한 구간은 E256 두 seed 모두 15/15, E512와 E1024는 각각 14/15가 된다. 세 조건이 모두 완료된 공통 **14구간**에서 다음 문자열 집계를 얻었다.

|항목|256(seed 17)+256(seed 29)|256(seed 17)+512(seed 17)|
|---|---:|---:|
|기준 256 관계 문자열|1,169|1,169|
|추가 관계 문자열|749|1,077|
|합집합 관계 문자열|1,918|2,246|

다른 크기를 추가하면 신규 관계 문자열이 328개(약 44%) 더 많았다. 구간 내 문자열 중복 제거 후 합산했으며 **유효한 신규 fact 수는 아니다.** 비용은 맞추지 않았고, 선택적으로 설정을 바꾼 복구 결과이므로 기존 동일 설정 실험과 구분한다.

이번 사전 실험에서는 **출력 반복도 잘림의 원인**임을 확인했다. 512토큰 입력 한 건은 43,120토큰을 출력했고, 관계 596항목 중 고유 ID triple은 18종이었다. 출력 상한 확대만으로 추출 품질을 해결하기 어렵다는 관찰이며, 이후 모델 교체에서는 반복 생성과 주체·대상 연결 오류 감소도 확인할 예정이다. 이번 추가 결과에 대한 의미적 유효성 평가나 QA 평가는 수행하지 않았다.
