# 청크 크기에 따른 entity/relation 추출 실험

## 연구 질문과 범위
동일 원문·동일 extractor에서 청크 크기에 따라 원문이 지지하는 entity와 relation이 달라지는가? 그 차이가 반복 추출 변동과 청크 경계 효과를 넘어서는가?
이번 단계는 extraction만 수행한다. GraphRAG 인덱스, 검색, QA, fusion 학습은 수행하지 않는다. 추출 개수 증가는 품질 향상을 뜻하지 않는다.

## 확인된 로컬 모델
Qwen3-VL-4B-Instruct, GGUF Q4_K_M. LocalStudy.app에 포함된 가중치와 llama-server를 이용한다. 일반 Qwen3-4B와 다른 모델이다. 모델 파일 해시, 서버 버전, 실행 옵션, 프롬프트와 입력 해시를 실행 기록에 저장한다. 이 파일럿의 결과는 이 extractor 설정에 한정한다.

## 표본과 실행 순서
1. 형식 점검: 직접 만든 짧은 예제 1개로 JSON 출력, relation endpoint, evidence 원문 일치 검사. 연구 결과로 집계하지 않는다.
2. 실데이터 파일럿: 기존 소설 5편에서 각각 2개, 총 10개 구간. 구간당 약 2,048 모델 토큰의 연속 원문. 제목·목차·머리말을 제외하고, 정답 질문을 보지 않고 고정 seed로 위치 선정. 구간 원문과 문자 offset을 고정한다. 표본 목록을 먼저 저장한다.
3. 파일럿 품질을 확인한 후 소설당 6개, 총 30구간으로 확대. 문서 전체 일반화에는 소설 수가 적다는 한계를 명시한다.

## 실험 조건
| 조건 | 목적 |
|---|---|
| E128 / E256 / E512, overlap=0 | 기존 실험과 연결되는 기본 비교 |
| 각 크기에서 3개 sampling seed | 동일 크기 변동과 크기 간 차이 비교 |
| E256의 경계를 128토큰만큼 이동, 3개 seed | 경계 위치 효과 비교 |
| 필요 시 E1024 추가 | 512 밖의 관찰 범위 효과 탐색. 기본 실험 후 확장 |

모든 조건은 같은 원문 전체를 빠짐없이 덮는다. 경계 이동 조건도 첫 prefix와 마지막 suffix를 포함한다. 동일 구간 안에서만 비교한다. 토큰 길이는 실제 모델 tokenizer로 측정하고, offset은 원문 문자 위치로도 저장한다. 토큰 배열을 임의로 decode해 원문을 변형하지 않는다.

샘플링은 모든 조건에서 동일한 non-thinking Instruct 설정을 사용한다. 초기 계획은 temperature=0.2, top_p=0.9, seed=[17,29,43]. 이는 권장 최적값이 아닌 실험 고정값이며 소규모 형식 점검 후 동결한다. Greedy 반복은 대체로 같은 출력을 내므로 stochastic variability의 대조군으로 사용하지 않는다.

2,048토큰 구간에서 크기별 약 16+8+4=28 호출, 3회 반복이면 약 84 호출이다. 10구간은 약 840호출이며 경계 이동 대조군은 추가다. 먼저 1구간 실행 시간과 출력 토큰을 측정하여 전체 규모를 확정한다.

## 동일 extraction schema
Entity: id, name, type, evidence(원문 그대로 인용).
Relation: source(entity id), predicate(짧은 관계 표현), target(entity id), evidence(원문 그대로 인용).
외부 지식·추측 금지. 불확실한 관계는 생략. 이름 없는 대명사의 외부 문맥을 추측하지 않는다. 문장 의미가 허용하면 청크 내부 공지시 해결 가능. 방향·부정·시점·가능성·화자의 주장 여부를 관계 표현 또는 보조 qualifier에 보존한다.
각 결과에 doc_id, region_id, chunk_id, token/char 시작·끝, size, seed, prompt hash, raw output, elapsed time, usage, finish_reason을 저장한다.
출력 상한은 모든 조건에서 충분한 동일 값으로 시작하되 잘린 출력을 빈 결과로 계산하지 않는다. 상한 도달률을 크기별 보고하고, 문제가 생기면 상한을 높여 해당 비교 조건 전체를 동일 정책으로 재실행한다. 재시도와 최초 실패 모두 기록한다.

## 자동 검사와 사람 검증의 구분
자동 검사: JSON 파싱, schema, entity id 중복, endpoint 존재, evidence의 원문 substring 일치, 출력 잘림.
이 검사를 통과해도 의미가 맞는 것은 아니다. 특히 evidence 문자열 존재를 relation 유효성 판정으로 사용하지 않는다.

사람 판정은 entity와 relation을 분리한다. 조건·크기·seed를 숨기고 무작위 순서로 검토한다.
- Entity: 실제 지시 대상인가? 이름·유형·공지시가 맞는가?
- Relation: 주체·대상·관계·방향·부정·시점·양태가 해당 입력으로 지지되는가?
- 라벨: supported / unsupported / ambiguous. ambiguous는 따로 보고한다.
- 입력 청크 기준 지지와 주변 전체 문맥에서의 진실성을 구분한다. 청크 밖에서만 확인 가능한 사실은 입력 근거 기반 precision의 supported로 처리하지 않는다.
- 주석자 2명이 독립 판정하고 불일치는 합의. 파일럿은 모든 고유 후보를 검토하거나 크기별·공통/고유별 층화 표본을 사전 고정한다. 표본 추정 시 포함 확률로 가중한다.

## 정렬과 지표
문자열 차이를 새 사실로 세지 않는다. 소설별 entity alias 표를 만들고, 관계의 의미·방향·시간·부정이 같을 때만 동일 fact로 묶는다. 정렬 전 원본과 provenance를 보존한다. 과도한 병합과 미병합 사례도 표본 점검한다.

1. Entity precision, relation precision: supported / 검토한 후보. ambiguous 포함·제외 결과를 함께 제시.
2. Valid yield: 중복 제거된 supported entity/fact 수 / 동일 원문 1,000토큰.
3. 크기별 고유 valid fact: 다른 크기에는 없고 해당 크기에 있는 supported fact 수. 각 seed 기준과 3개 seed pooled 기준을 구분.
4. 반복 안정성: 동일 크기 seed 간 정렬된 fact Jaccard와, 서로 다른 크기 간 Jaccard 비교. 차이가 크다는 것만으로 유효성을 주장하지 않음.
5. 상대 coverage: 사람이 검증한 모든 조건의 합집합을 분모로 하는 pooled coverage. 완전한 gold recall이라고 부르지 않음.
6. 추가 coverage: union이 최선의 단일 크기 대비 추가하는 유효 fact 수·비율.
7. 비용: input/output tokens, 호출 수, 실제 시간, parsing/truncation 실패율, 정렬·검증 비용.

추출되지 않은 사실까지 포함한 recall을 주장하려면 별도의 원문 구간에서 독립 gold fact 주석이 필요하다. pooled 후보 평가만으로 recall을 주장하지 않는다.

## 핵심 대조와 통계
Multi-scale union을 비용이 비슷한 single-scale repeated union과 비교한다. 반복 횟수가 같다는 이유로 비용이 같다고 보지 않고 실제 input+output 처리량과 시간에 따른 곡선을 제시한다. 실행 순서를 섞고 cache 정책을 고정한다. 최선의 scale 선택은 개발 표본에서 하고 평가 표본에 고정하거나, 평가 내 최댓값이면 oracle이라고 표시한다.
문서·원문 구간을 paired unit으로 사용한다. fact/청크를 서로 독립 표본으로 간주하지 않는다. 소설별 결과 및 구간별 차이를 보고하며, 작은 문서 수에서 CI를 과신하지 않는다.

## 진행 판단
원문이 지지하는 고유 relation이 여러 소설에서 재현되고, 동일 크기 반복·경계 이동·추가 비용만으로 설명되지 않을 때 fusion 설계로 진행한다. Entity만 늘고 유효 relation이 늘지 않으면 핵심 가설의 근거가 부족하다. 4B 모델의 출력 오류가 많으면 extraction 프롬프트를 개발 표본에서 수정하거나 별도 모델 검증을 진행하고, 변경 전후 실험을 섞지 않는다.

## 현재 상태
설계 후 공식 GraphRAG-Bench Novel corpus를 직접 다운로드하여 2문서 × 1,024토큰의 축소 파일럿 36건을 완료했다. 위 5문서 × 2구간 설계는 후속 확대 계획이다. 실제 설정·수치·오류는 청크별_추출_실험결과.md 참조.
