# E1024 추가 비교

기존 두 문서의 각 1,024토큰 구간 전체를 한 청크로 입력했다. 문서 전체를 입력한 실험은 아니다. E128/E256/E512의 원문·프롬프트·seed 17·모델·생성 설정을 유지했다. E1024만 뒤에 실행했으므로 호출 순서를 무작위로 섞은 추가 실험은 아니다.

기존 36회 + E1024 2회. 최대 출력은 기존과 동일하게 4,096토큰이다. 크기에 따라 출력 상한의 영향이 다를 수 있다. 잘림/파싱 실패/미완료가 있는 조건은 완전한 그래프로 비교하지 않는다.

## E1024와 관계 집합 비교

고유 relation 수와 Jaccard는 의미적 유효성 점수가 아니다. 부분 정렬은 이전 분석의 별칭·방향 규칙을 변경 없이 적용했다. E1024의 새로운 표현을 모두 정렬하지는 못한다.

## 원문 대조 진단

여행 문서의 E1024는 `The Devil's Frying Pan → is near → Lizard`를 만들었지만 인용 근거는 `THE DEVIL'S FRYING PAN, NEAR CADGWITH.`이다. 근거가 가리키는 장소는 Cadgwith여서 해당 근거가 추출된 pair를 지지하지 않는다. E512는 Cadgwith로 연결했다. E1024의 자동 오류가 0이어도 의미적으로 모두 맞는다는 뜻이 아니다.

E128에서 추출한 소녀의 Board School 미방문 관계는 E1024 결과에도 없다. 넓은 입력을 주었다고 세부 사실을 모두 회수하지는 않았다. 이는 assistant의 사례 대조이며 전체 precision 측정이 아니다.

청크별로 추출한 뒤 원래 문서 단위로 합쳐 중복을 제거한 결과다. E1024는 한 번에 더 넓은 맥락을 보지만, 작은 청크 조건은 호출 횟수와 총 출력 예산이 더 크다. 이번 비교만으로 동일 비용에서 어느 크기가 우수한지 결론 내릴 수 없다.

현재 구현은 청킹 + entity/relation 추출 및 비교까지다. 검색과 답변 생성, gold 기반 정확도/재현율, QA 점수는 아직 측정하지 않았다.

## 재현

```bash
python3 experiments/pilot/prepare_e1024.py --out runs/e1024
python3 experiments/pilot/run_chunk_pilot.py --corpus data/novel.json --out runs/e1024
python3 experiments/pilot/compare_pilot.py --extra-raw runs/e1024 --out runs/e1024_comparison.json
```

저장된 결과 재계산:

```bash
python3 experiments/pilot/compare_pilot.py --extra-raw experiments/pilot/e1024_raw --out experiments/pilot/e1024_comparison.json
python3 experiments/pilot/report_e1024.py
```

## 출력 상한 민감도: 호텔 기록 문서

E1024가 잘린 Novel-10146만 최대 출력 토큰을 4,096에서 6,144로 늘렸다. 입력·프롬프트·seed·context는 유지했다. 이는 조건을 변경한 별도 진단이며 위의 동일 설정 비교에 합치지 않는다.

정상 종료: 고유 entity 명칭 49개, 연결 가능한 고유 relation 30개. 자동 오류 항목 6개. 생성 토큰 4469개. 유효 fact 수가 아니다.

재현: 저장된 `e1024_budget6144_raw/manifest.json`을 새 폴더에 복사한 뒤 `run_chunk_pilot.py --corpus data/novel.json --out 새폴더 --max-tokens 6144`를 실행한다.
