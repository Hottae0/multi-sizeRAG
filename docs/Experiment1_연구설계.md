# Experiment 1 — 전체 원문 그래프의 유효 상호보완성

## 1. 연구 목표와 범위

최종 목표는 서로 다른 추출 granularity의 유효 상호보완성을 활용하는 새로운 GraphRAG 방법론입니다.
Experiment 1에서는 그 전제인 유효 신규 관계를 검증합니다. Fusion, progressive refinement,
검색·QA 개선을 이미 검증했다고 주장하지 않습니다.

실행 대상은 GraphRAG-Bench Novel **20문서의 전체 원문**입니다.
기존 5문서 × 3구간 × 4,096토큰, 1,140개 응답은 과거 사전실험이며 변경하거나 전체 원문 결과로 재표기하지 않습니다.
기존 `expanded/`, `pilot/`, Experiment 1의 `results/`는 보존합니다.

## 2. 문서당 기본 추출 조건: 5개

|조건|크기|Seed|Boundary|
|---|---:|---:|---:|
|A|128|17|0|
|B: 공통 기준|256|17|0|
|C|512|17|0|
|D|1024|17|0|
|E: 동일 크기 반복|256|29|0|

같은 전체 원문을 각 조건으로 모두 덮습니다. Overlap=0이며 마지막 짧은 청크까지 유지합니다.
문서당 기본 그래프는 5개입니다. Literal/semantic은 같은 조건의 정렬 전후 표현이지 추가 추출 조건이 아닙니다.
LLM 호출 수는 문서 길이·tokenizer·조건별 청크 수로 결정되며 5회가 아닙니다.
기본 구성에서는 모든 크기에 seed29를 추가하지 않습니다.
Boundary64나 다른 크기의 반복은 별도 후속 대조군이며 현재 study의 기본 5조건에는 포함하지 않습니다.

모든 조건은 같은 모델·tokenizer·프롬프트·decoding·출력 상한을 사용합니다.
Gleaning=0, 청크당 한 번 요청, 자동 재시도=0입니다.
CUDA 서버의 BF16 등 정밀도·chat template·generation config도 동일하게 고정합니다.

## 3. 하나의 실험, 두 가지 핵심 분석

### 3.1. 크기별 비교

128–256, 128–512, 128–1024, 256–512, 256–1024, 512–1024의 **6쌍**을 비교합니다.
Jaccard는 대칭이지만 신규 관계는 방향성이 있으므로 **12방향**을 계산합니다.

### 3.2. 동일 크기 반복 대비 다른 크기 추가

- 같은 크기: G256(seed17) ∪ G256(seed29)
- 다른 크기: G256(seed17) ∪ G512(seed17)

공통 기준 B에 대해 E−B와 C−B의 유효 신규 관계와 추가 비용을 비교합니다.
문서별 주 지표는 `다른 크기 추가의 유효 신규 수 − 같은 크기 반복의 유효 신규 수`입니다.
같은 크기 반복 쌍의 양방향 2개를 포함하여 기본 분석 결과는 모드당 문서당 **14방향**입니다.
별도 합집합 추출을 요청하지 않고 저장된 그래프를 재사용합니다.

## 4. 전체 원문 1 → 5 → 20문서 확장

|단계|대상|목적|조건별 문서 그래프 누적 수|
|---|---|---|---:|
|1|개발군에서 미리 지정한 1문서 전체 원문|파이프라인·생성 오류·시간·메모리 및 사례를 확인합니다.|5|
|5|첫 문서를 포함한 개발 5문서 전체 원문|현상과 비용을 확인하고 최종 프로토콜·판정 정책을 정합니다.|25|
|20|개발 5문서 + 미관찰 평가 15문서 전체 원문|설정을 고정한 뒤 주 평가를 수행합니다.|100|

개발군은 Novel-10146, Novel-30752, Novel-41603, Novel-44557, Novel-54537입니다.
첫 문서 기본값은 Novel-10146이며 init 때 개발군 중 하나로 변경할 수 있습니다.
나머지 15문서는 corpus 목록에서 자동으로 분리합니다. Corpus가 20문서가 아니거나 ID가 중복되면 거부합니다.

1→5는 4문서를 추가하고, 5→20은 15문서를 추가합니다. 동일 설정이면 앞선 결과를 재사용합니다.
문서 중간 일부를 샘플링하는 단계는 없습니다. 결과가 유리한 문서로 첫 문서를 교체하지 않습니다.
단계 확대는 연구자가 오류·비용·현상을 보고 결정합니다. 코드가 긍정적 결과만 골라 자동 확대하지 않습니다.
첫 문서에서 다른 크기가 반드시 이겨야 하는 것은 아닙니다.

모델·프롬프트·출력 상한·정렬/판정 정책을 바꾸려면 새 study를 만듭니다.
최종 설정과 달랐던 개발 문서는 새 study에서 다시 추출하여 총 20문서를 동일 프로토콜로 처리합니다.
최초 개발 비용과 최종 재추출 비용은 별도로 기록하고 총 연구 비용에서 숨기지 않습니다.
`freeze`는 5개 개발 문서의 추출 시도·분석 저장을 확인하고 판정 정책/확대 결정을 기록합니다.
실제 의미 검토를 대신하지 않습니다. 나머지 15문서의 추출은 freeze 이후에만 허용합니다.
평가 결과를 보고 유리한 설정을 선택하지 않으며 개발군·평가군 결과를 분리합니다.

## 5. 문서별 처리 순서와 재개

각 문서를 하나의 full-source region으로 표현하여 다음을 수행합니다.

1. 전체 원문 토큰화 → 명시적 5조건 청킹 → coverage 검증을 수행합니다.
2. 그 문서의 모든 조건을 single-pass 추출합니다.
3. 오류 점검과 점검용 literal 그래프를 저장하고 나서 다음 문서로 이동합니다.
4. 문서별 occurrence를 의미 정렬하고, 정렬된 조건별 semantic 그래프를 구축합니다.
5. 조건을 가린 독립 원문 판정 후 유효 신규 관계·비용을 집계합니다.

의미 정렬·원문 판정은 GPU 추출과 별도 검토 작업입니다. GPU가 다음 문서를 처리하는 동안 이전 문서를 검토할 수 있습니다.
주 분석 순서는 extraction → semantic alignment → semantic graph → 비교·원문 판정입니다.
초기 literal 그래프를 의미 정렬 완료 결과로 간주하지 않습니다.

원문·프로토콜·코드·raw hash를 연결하며 문서별 run은 불변입니다. 확장 시 전체 manifest를 바꾸지 않습니다.
재개 시 성공·실패·결과 불명 started 요청을 모두 재요청하지 않습니다.
분석 snapshot은 입력 hash에 따라 생성하고, 중단된 분석 디렉터리는 보존한 채 다시 계산합니다.
오류 호출을 재추출하려면 별도 study/run으로 수행하고 실패를 성공 결과로 덮어쓰지 않습니다.

## 6. 그래프와 의미 정렬

Entity=node, 방향성 relation=edge인 multigraph를 조건별로 구성합니다.
동일 edge의 occurrence와 문서·청크·seed·크기·boundary·raw hash·원문 span을 모두 보존합니다.
개별 청크 그래프를 별도 주요 분석 단위로 추가하지 않습니다. 청크 출처는 occurrence로 추적합니다.
문서 간 entity는 병합하지 않습니다. 문서 내부 literal 이름 정규화도 실제 동일성 판정과 구분합니다.

의미 정렬은 검토된 entity/fact occurrence class를 적용합니다. 자동 embedding/LLM 판정기는 포함하지 않습니다.
별칭·동명이인·방향·극성·시점·조건을 확인하고 equivalent만 묶습니다.
정렬이 없으면 semantic 결과는 unavailable이고, 미완료 정렬은 탐색용입니다.
다른 크기의 fact/evidence를 한 조건의 그래프에 주입하지 않습니다.
QA용 기준선은 비교용 cross-size 정렬과 별도로 설계해야 합니다.

## 7. 평가와 비용

- 집합: literal/semantic node·edge Jaccard, 신규 후보, union 크기를 봅니다.
- 구조: 성분·고립 node, 기존 성분을 잇는 추가 edge, union의 신규 2-hop 경로를 봅니다.
- 근거: 새 원문 span과 기존 근거가 덮지 못한 문자를 봅니다.
- 유효성: **원문 지지 AND 기준 대비 의미 신규**를 독립 판정합니다.
- 비용: 모든 호출·토큰·요청 시간·단계 실행 시간·메모리와 오류를 기록합니다.

전체 5조건의 모든 청크가 정상 생성된 문서를 공통 비교 대상으로 사용합니다.
실패 문서는 부분 그래프·오류·비용은 남기고 주 비교에서 제외합니다. 표본 수 감소와 제외 편향을 보고합니다.
긴 문서의 실패가 많다면 개발 단계에서 프로토콜을 재검토하며, 평가 후 제외 규칙을 유리하게 바꾸지 않습니다.
정상 생성은 의미적 정확성이 아닙니다. 잘린 응답은 복구하지 않고 전체 제외하며 항목 오류는 격리합니다.

문서×방향×신규/공통 층별 표집과 포함확률을 보존합니다.
판정자는 조건·층을 가린 claim, 원문, 기준 그래프의 전체 claim을 봅니다.
전체 문서에서 중복 저장을 줄이기 위해 baseline은 `review_baselines.json`에 한 번 저장하고
`review_blind.json`의 opaque `baseline_ref`로 연결합니다. 반드시 두 파일과 원문을 함께 제공합니다.
두 판정자의 독립 검토와 불일치 합의는 외부에서 수행하며 최종 파일을 입력합니다.

완료된 판정만 HT 유효 신규 수로 추정합니다. 미판정을 false로 채우지 않습니다.
개발/평가별 문서 macro 지표와 주 비교의 대응 차이를 집계합니다.
문서 2개 이상에서만 문서 재표집 bootstrap 구간을 제공합니다. 이는 주석·층화 표집 불확실성까지 포함한 구간이 아닙니다.
판정자 일치도 계산 및 주석 표집 오차까지 반영한 추론은 현재 자동 구현 범위 밖입니다.
동일 비용 우수성·gold recall·경로 recall·QA 향상을 주장하지 않습니다.

## 8. 실행 환경과 구현 상태

목표 환경은 Linux, CPU 4코어, RAM 128GB, A100 80GB 1개, 저장공간 500GB입니다.
새 CUDA backend는 PyTorch/Transformers로 모델 전체를 cuda:0에 적재하며 CPU offload/fallback은 하지 않습니다.
모델은 미확정이며 로컬 HF text instruct checkpoint 또는 고정 Hub revision을 명시해야 합니다.
기본 BF16·context8192·output4096은 시작 설정이며 첫 개발 문서에서 확인한 뒤 고정합니다.

구현: 전체 원문 catalog, 5조건, 단계별 확장, protocol freeze, 문서별 추출/분석 재개,
검토 정렬 적용, 독립 그래프, 14방향 비교, blind 평가표, 개발/평가 분리 집계, CUDA 연결 및 메모리 기록입니다.
미수행: 실제 A100 모델 적재·추론 성능 검증, 실제 corpus의 의미 정렬·독립 원문 판정, fusion·QA 검증입니다.

긴 문서를 위해 UTF-8 경계 계산을 선형화하고 manifest hash 반복 계산과 baseline 반복 저장을 줄였습니다.
2-hop 경로가 설정한 상한을 넘으면 해당 경로 지표를 null로 표시합니다. 0이나 정확한 개수로 보고하지 않습니다.
`--alignment-pairs`의 기존 전수 관계 쌍 생성은 여전히 O(R²)이며 전체 문서 study에서는 자동 실행하지 않습니다.
대규모 의미 정렬의 후보 검색·검토 효율화는 후속 작업입니다.

실행 명령은 [전체 문서 실행 안내](../experiments/experiment1/FULL_DOCUMENTS.md)를 확인해 주세요.
